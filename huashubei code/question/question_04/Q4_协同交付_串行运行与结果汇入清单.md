# Q4协同交付、串行运行与结果汇入清单

适用范围：V3文档合规版Q4。基准完成并通过“Q4 · 00A · 文档级审计（V3，只读）”后，再按本清单压缩、发送和分工。

## 1. 00A是什么

“Q4 · 00A · 文档级审计（V3，只读）”对应命令`--baseline-audit`。

- 它**不重新优化**，不调用MILP，不会修改、覆盖或删除基准结果。
- 它读取已经完成的V3基准任务表、能源表、汇总表和完成标记，独立复算并核验：任务唯一执行、实时任务到达即启动、网络时延、最早开工与完成期限、GPU/IT/设施容量、新能源平衡、购售电边界、SOC递推、充放电互斥、终端SOC，以及六项指标的一致性。
- 只有V3基准已完整结束且完成标记中的`audit_passed=true`时，00A才会返回成功；否则明确拒绝，不会回退使用旧V2结果。
- 因此，00是“求解并生成基准”，00A是“交付前只读复核”。

## 2. 发给队友前的基准验收

在PyCharm先完成：

1. 运行“Q4 · 00 · 文档合规基准（V3，自动续跑）”。
2. 运行“Q4 · 00A · 文档级审计（V3，只读）”。必须显示`passed=True`，并且进程退出码为0。
3. 检查下列文件均存在：

```text
question/question_04/outputs/matheuristic_v3_doccompliant/tables/
  .q4_matheuristic_v3_complete.json
  q4_task_assignments.csv
  q4_region_hour_dispatch.csv
  q4_objective_summary.csv
  q4_window_solver.csv
  q4_scaling.csv
  q4_model_configuration.csv
  q4_simple_validation.csv
  q4_calibration_records.csv
  q4_forecast_profile.csv
```

4. 打开`.q4_matheuristic_v3_complete.json`，确认至少有：

```json
"complete": true,
"audit_passed": true,
"model_version": "Q4_MATHEURISTIC_V3_DOCUMENT_COMPLIANT"
```

5. 只在上述四项均满足后压缩。不要在基准仍运行、只存在检查点时发送给队友作为共同基准。

## 3. 建议压缩内容

压缩时保持项目的相对目录结构，解压后根目录仍应为`huashubei/`。不需要压缩`.venv/`，以免压缩包过大、也避免把本机Python环境带过去。

### 必须包含

```text
huashubei/

    Q4_情景运行说明.md
  question/question_01/data/processed/shared/
    tasks_clean.csv
    task_candidate_regions.csv

    outputs/matheuristic_v3_doccompliant/

```

### 可选包含

- `question/question_04/outputs/matheuristic_v2/`：仅用于保留历史诊断，不是V3情景运行所必需。
- `question/question_04/outputs/source_backups/`：仅用于保留代码备份，不是运行所必需。
- 已完成的`question/question_04/outputs/scenarios/<scenario-name>/`：用于让队友查看或继续汇总；不要发送不完整情景目录。

### 不建议包含

- `.venv/`、`.idea/`、`__pycache__/`。
- 正在运行的情景检查点，除非明确要把该情景交给另一台电脑**接力续跑**，且两台电脑不会同时运行它。

## 4. 队友环境核对

推荐环境：Python 3.12；当前验证环境为Python 3.12.13、NumPy 2.5.1、Pandas 3.0.5、SciPy 1.18.0。

若队友没有可用环境，可在项目根目录创建虚拟环境后安装：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install numpy pandas scipy
```

在PyCharm中将解释器指定为`$PROJECT_DIR$/.venv/Scripts/python.exe`，然后先运行“Q4 · 00A · 文档级审计（V3，只读）”。审计通过才开始接手情景。

## 5. 串行运行顺序

单机、单人完全串行时，严格按以下顺序：

1. Q4 · 00：V3基准。
2. Q4 · 00A：V3只读审计。
3. Q4 · 01：低碳参考。
4. Q4 · 02：碳约束`λ=0.25`。
5. Q4 · 03：碳约束`λ=0.50`。
6. Q4 · 04：碳约束`λ=1.00`。
7. Q4 · 05：平价电价。
8. Q4 · 06：新能源平滑`γ=0.25`。
9. Q4 · 07：新能源平滑`γ=0.50`。
10. Q4 · 08：新能源平滑`γ=1.00`。
11. Q4 · 09：情景比较汇总（只读）。

低碳参考必须在全部碳约束之前完成。平价电价和三个新能源平滑情景只依赖V3基准；它们在逻辑上不依赖低碳参考，但同一台电脑仍建议一次只运行一个大模型。

## 6. 两台电脑的推荐分工

在共同V3基准已通过00A后，可提高效率：

| 人员 | 串行任务 | 前置条件 |
| --- | --- | --- |
| A | 低碳参考 → λ=0.25 → λ=0.50 → λ=1.00 | 共同V3基准；每个λ均等待低碳参考完成 |
| B | 平价电价 → γ=0.25 → γ=0.50 → γ=1.00 | 共同V3基准 |

两人各自机器内部保持串行；A和B可以同时运行不同情景。不要两台电脑运行同一个`scenario-name`，也不要对同一个输出目录做双向复制。

## 7. 中断、失败与续跑

- 中断、异常退出或电脑重启后：在**原机器**重新运行相同PyCharm配置即可续跑。
- 不要删除该情景的`matheuristic_v3_doccompliant/tables/`、检查点或进度CSV。
- 不要为了重跑而使用同一个情景名创建新目录；签名不同或目录不完整时，程序会拒绝覆盖以保护已有结果。
- 若要交接未完成任务：完整复制该情景的整个`outputs/scenarios/<scenario-name>/`目录到另一台电脑；确认源机器已经停止该配置后，再在目标机器运行同一配置。
- 仅在出现明确异常信息时记录错误全文；不要手动修改CSV、JSON或PKL检查点。

## 8. 完成结果的汇入规则

每个完成情景都应具备：

```text
outputs/scenarios/<scenario-name>/matheuristic_v3_doccompliant/tables/
  .q4_matheuristic_v3_complete.json
  q4_task_assignments.csv
  q4_region_hour_dispatch.csv
  q4_objective_summary.csv
  q4_scenario_metadata.json
```

汇入主项目时：

1. 只复制已完成且`audit_passed=true`的整个`<scenario-name>/`目录。
2. 复制到主项目的`question/question_04/outputs/scenarios/`下，保留原有目录名，不重命名内部文件。
3. 不复制或覆盖主项目的`outputs/matheuristic_v3_doccompliant/`基准目录。
4. 不将V2目录、旧`low_carbon_reference_guarded`目录或未完成检查点作为情景正式结果汇入。
5. 全部情景汇入后，在主项目运行“Q4 · 09 · 情景比较汇总（只读）”。它会生成：

```text
question/question_04/outputs/scenarios/q4_matheuristic_v3_scenario_comparison.csv
```
