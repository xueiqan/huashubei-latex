# Python Programs for Huashu Cup Problem C

Programs for demand forecasting, computing dispatch, storage optimization, and joint computing-storage-power optimization. See the [repository README](../README.md) for the project overview, paper, and frozen submissions.

## Set up and run

Open this directory in PyCharm and select `.venv/Scripts/python.exe` as the interpreter. The existing local environment was retained during the directory move. For a fresh checkout, run `uv sync --frozen` here to synchronize the environment from `pyproject.toml` and `uv.lock`. Python 3.12 or later is required.

Run the per-question entry points in order:

```powershell
uv run python question/question_01/main.py
uv run python question/question_02/main.py
uv run python question/question_03/main.py
uv run python question/question_04/main.py
```

To use an existing environment without dependency synchronization, replace `uv run python` with `uv run --no-sync python`. In PyCharm, right-click the relevant `main.py` and select **Run**. These entry points start actual computations; preserve historical results and allow sufficient solver time.

## Source, inputs, and results

Each question follows `preprocess.py -> model.py -> validation.py -> plot.py`. There are 24 active Python files. Q2 also includes exact/heuristic comparison, single-window heuristic, and isolated-validation tools.

```text
question/
├── question_01/
├── question_02/
├── question_03/
└── question_04/
    ├── main.py
    ├── preprocess.py
    ├── model.py
    ├── validation.py
    ├── plot.py
    ├── data/
    │   ├── raw/
    │   └── processed/
    └── outputs/
```

The six Q1 Excel attachments are in [question/question_01/data/raw/](question/question_01/data/raw/). Q1 produces shared inputs in `question/question_01/data/processed/shared/`; Q2-Q4 read this layer to create their own inputs. Preserve filenames and directory levels. Model parameters remain in the corresponding source files.

Each question keeps tables, figures, logs, formal version directories, and checkpoints in its own `outputs/`. Historical Q1 results are in [archive/legacy-results/question_01/](../archive/legacy-results/question_01/), and old Q4 source is in [archive/source-backups/question_04/](../archive/source-backups/question_04/).

Q2's `validation_runs.py` prepares or archives isolated K24/K72 experiments. It derives `code_q2_validation_runs/` at the repository root from the code directory name. That directory is generated by experiment commands. Saved Q2 run configurations use project-relative paths; use the tool's `prepare` command before starting an isolated experiment.

## Q4 checks

```powershell
uv run python question/question_04/model.py --help
uv run python question/question_04/validation.py --help
uv run python question/question_04/model.py --self-test
uv run python question/question_04/model.py --baseline-audit
uv run python question/question_04/validation.py --skip-reference-windows
```

The self-test covers structure and local algorithm checks. Baseline auditing and independent validation require complete results from the matching version. `--skip-reference-windows` skips representative-window MILP solves while auditing existing files. Default validation can start those solves. See the [Q4 runbook](question/question_04/q4-runbook.md) for detailed commands and evidence boundaries.

## Versions and verification

Q4 uses `matheuristic_v4_doccompliant`; V3 historical results and V4 energy recomputations for fixed task plans are also retained. Full joint searches, fixed-task energy recomputations, and archived validations have different completion criteria and metrics.

Q2-Q4 main entry points may return 0 after logging validation/plotting warnings. Check the actual logs, reports, and expected outputs. Passing model checks does not establish global optimality.

The directory move was checked through environment imports, entry-point help, source parsing, and file hashes. It did not rerun the full four-question solve. The English translation changes authored text and display messages; original inputs, existing outputs, and frozen evidence remain unchanged. Required legacy schema/path values are retained where needed to read existing files.
