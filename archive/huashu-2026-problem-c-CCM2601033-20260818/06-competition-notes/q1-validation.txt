对，前一版还不够“狠”。按你这份**模型检验提示词**，检验不是“多做几个图”，而是必须直接攻击当前模型最可能被评委质疑、且一旦失败会改变模型选择或论文结论的地方。每项都要形成完整判断链：**防守对象 → 检验设计 → 指标 → 明确判据 → 失败后怎么办**。 

结合现在Q1已经确定的“**分层小时预测 + 两级基础调度**”，我建议最终只做 **3项高强度检验**。这三项已经足以覆盖Q1的可信度命门，不再堆普通灵敏度分析。

# 问题1模型检验设计

## 一、当前结论最需要防守的三个风险

Q1真正需要防守的不是“代码有没有报错”，而是以下三个结论。

第一，预测模型的核心判断是：

> **细粒度需求随机性强，而适度聚合后的区域、类型和系统小时需求具有更稳定的短期可预测性。**

这一结论最大的风险是：目前看到的“聚合后WAPE下降”可能只是某一个24小时窗口的偶然现象，而非稳定规律。

第二，分层模型不是直接预测18个“区域×类型”交叉单元，而是先预测区域边际、类型边际和系统总量，再恢复18类结构。因此必须防守：

> **这种聚合—恢复过程没有为了降低总体误差而严重扭曲不同区域、不同类型之间的真实结构。**

第三，调度得到的核心结论是：

[
F_1^*=0,\qquad LocalRatio=100%,
]

也就是最后24小时实际任务完全可以本地完成。当前约束零违反只能证明“这一个方案可行”，真正有价值的问题是：

> **这个结论是不是严格最优，而且离容量边界还有多远？稍微加大任务压力后，什么时候会第一次需要迁移？**

这三项正好对应：

[
\boxed{
\text{预测泛化}
\rightarrow
\text{分层结构有效性}
\rightarrow
\text{调度最优性与稳健边界}
}
]

不需要再另外做GPU±10%、时延±10%、功率±10%这种没有数据依据的机械摄动。提示词明确要求不能凭空设置扰动比例。

# 检验一：多窗口滚动时间外预测检验

这是预测部分**最重要、也是最有力的一项检验**。

### 检验设计

官方只给出了一个24小时验证区间2352—2375。如果模型只在这一天表现较好，很难证明它具有一般性的短期预测能力。因此在**0—2351小时内部**构造多个严格前向的24小时预测窗口，每次只允许使用预测时点以前的信息。

设第 (m) 个预测原点为 (T_m)，则：

[
\mathcal T_m^{train}
====================

{0,\ldots,T_m},
\qquad
\mathcal T_m^{test}
===================

{T_m+1,\ldots,T_m+24}.
]

为避免高度重叠窗口人为放大样本量，采用**互不重叠的连续24小时窗口**。可以优先覆盖训练区间最后若干周；具体可用窗口数由数据自动确定，不人为凑数量。

每个窗口完整重复正式模型流程，同时计算：

* 18类底层序列；
* 6条区域序列；
* 3条任务类型序列；
* 1条全系统序列。

并比较候选历史窗口

[
H\in{24,72,168,336}
]

以及唯一简单基准：

[
\hat D_t^{base}=D_{t-24}.
]

这样一项检验同时回答两个问题：

1. 最终选定的 (H^*) 是否只在官方验证日偶然有效；
2. “聚合尺度越高，可预测性越强”是否在多个时间窗口内稳定出现。

### 判断指标

每个滚动窗口分别计算：

[
WAPE_m=
\frac{\sum_t|D_t-\hat D_t|}
{\sum_tD_t},
]

同时保留MAE、RMSE辅助识别尖峰误差。

更重要的是，不只比较平均值，而计算模型与基准的**成对损失差**：

[
\Delta_m
========

## WAPE_m^{main}

WAPE_m^{base}.
]

若主模型稳定更优，则应有：

[
\Delta_m<0
]

在多数窗口出现。

为了避免只凭“多数”做主观判断，对滚动窗口的 (\Delta_m) 进行**Wilcoxon符号秩检验**：

[
H_0:\operatorname{median}(\Delta_m)=0,
\qquad
H_1:\operatorname{median}(\Delta_m)<0.
]

采用常规显著性水平：

[
\alpha=0.05.
]

这里的0.05来自标准统计显著性准则，而不是人为构造模型阈值。

### 明确判据

若同时满足：

[
p<0.05
]

且：

[
\operatorname{median}(\Delta_m)<0,
]

则可以写：

> 主模型相对于24小时同刻基线具有统计上稳定的样本外误差优势。

对于聚合尺度，则比较：

[
WAPE^{R\times K},
\quad
WAPE^R,
\quad
WAPE^K,
\quad
WAPE^S.
]

如果“细粒度→区域/类型→系统”的误差下降在大多数历史窗口均出现，并且各尺度WAPE的中位数保持同样排序，则能够有力支撑：

> 预测困难主要来自底层任务随机到达，而不是模型遗漏了稳定时间规律。

### 如果不通过

如果 (H^*) 只在2352—2375验证期表现好，而滚动窗口中长期不占优：

> **不能继续把该窗口写成稳定主模型参数。**

应改为滚动检验表现最稳定的窗口，或者直接采用24h同刻基线。

如果聚合误差下降只发生在最后一个窗口，则不能把“聚合提高可预测性”写成普遍结论，只能限定为当前测试时段的现象。

# 检验二：分层预测的结构恢复有效性检验

第一个检验证明的是“预测有泛化能力”，但还没有证明：

> **聚合以后再恢复18类需求，真的比直接预测18条随机序列合理。**

这是第二个必须攻击的风险。

## 2.1 检验设计

继续使用检验一的历史滚动窗口。

对于每个窗口，都已经知道未来24小时真实的18类需求：

[
D_{rkt}^{true}.
]

分别构造两种结果。

**直接法**：对18条底层序列分别使用相同局部预测结构，得到

[
\hat D_{rkt}^{direct}.
]

**分层法**：按照正式模型先预测：

[
\hat D_{rt},\qquad
\hat D_{kt},\qquad
\hat D_t,
]

完成边际一致性校正，再利用历史区域—类型结构恢复：

[
\hat D_{rkt}^{hier}.
]

比较对象完全同口径，因此不存在“不同算法、不同评价口径”的问题。

---

## 2.2 第一层：代数一致性必须严格通过

首先检查：

[
e_t^R
=====

\left|
\sum_r\tilde D_{rt}-\hat D_t
\right|,
]

[
e_t^K
=====

\left|
\sum_k\tilde D_{kt}-\hat D_t
\right|.
]

这是硬性检查，不是统计意义上的“大致接近”。

### 判据

只允许浮点数数值误差：

[
\max_t(e_t^R,e_t^K)\le\varepsilon_{num},
]

其中 (\varepsilon_{num}) 使用程序数值精度或优化求解容差，不人为定义现实误差带。

如果不能达到数值精度意义上的0，说明恢复程序本身存在错误，模型直接判定失败。

---

# 2.3 第二层：历史结构先验是否稳定

分层恢复依赖历史区域—类型占比：

[
q_{rk}.
]

因此真正的命门是：

> 最近历史中的18类结构是否能够代表未来24小时？

对训练区间构造连续历史窗口，计算每个窗口的18维归一化需求占比：

[
q_{rk}^{(m)}
============

\frac{
\sum_{t\in W_m}D_{rkt}
}{
\sum_{r,k,t\in W_m}D_{rkt}
}.
]

使用 Jensen–Shannon 距离衡量相邻窗口结构变化：

[
JS
\left(
q^{(m)},q^{(m+1)}
\right).
]

这里不人为规定“JS<0.1就稳定”，而采用**数据自身形成的经验稳定区间**。

设历史窗口JS距离的95%经验分位数为：

[
Q_{0.95}^{JS}.
]

正式验证期结构与其前一历史窗口之间计算：

[
JS_{val}.
]

### 判据

若：

[
JS_{val}
\le
Q_{0.95}^{JS},
]

则验证期结构变化仍属于历史正常波动范围，历史占比 (q_{rk}) 作为恢复先验有数据支撑。

若：

[
JS_{val}>Q_{0.95}^{JS},
]

说明区域—类型业务结构发生了异常漂移，则不能继续采用固定历史结构恢复，应缩短结构估计窗口或采用动态占比。

这个阈值完全来自训练数据自身，而不是拍脑袋设置。

---

# 2.4 第三层：恢复后的18类结果是否真正改善

计算：

[
WAPE^{hier}
===========

\frac{
\sum_{r,k,t}
|D_{rkt}^{true}-\hat D_{rkt}^{hier}|
}{
\sum_{r,k,t}D_{rkt}^{true}
},
]

与：

[
WAPE^{direct}
=============

\frac{
\sum_{r,k,t}
|D_{rkt}^{true}-\hat D_{rkt}^{direct}|
}{
\sum_{r,k,t}D_{rkt}^{true}
}.
]

对多个滚动窗口形成：

[
\Delta_m^{hier}
===============

## WAPE_m^{hier}

WAPE_m^{direct}.
]

同样使用成对Wilcoxon检验。

### 通过判据

如果：

[
\operatorname{median}
(\Delta_m^{hier})<0
]

且单侧检验：

[
p<0.05,
]

可以比较有力地写：

> 分层恢复相对于直接预测18条稀疏序列具有稳定的样本外误差优势。

如果：

[
p\ge0.05,
]

但二者误差接近，也不能写“分层预测显著更准”；此时应把优势限定为：

> 分层模型在保持区域和类型边际一致性的同时，没有造成明显的底层预测损失。

如果分层法明显更差，则正式预测结论必须停留在：

[
6\text{区域}+3\text{类型}+1\text{系统}
]

层面，不应强行声称18个交叉单元具有可靠预测精度。

# 检验三：调度最优性证书与临界负载压力检验

这是Q1调度端最应该做强的一项。

普通“所有约束均满足”只能证明**当前方案可行**。

真正强的检验应该进一步证明两件事：

1. (F_1^*=0) 是不是严格的全局最优；
2. 当前“无需迁移”距离失效边界到底还有多少余量。

---

## 3.1 一级目标的严格最优性证明

一级目标为：

[
F_1
===

\sum_i
\sum_{\substack{r\ne Source_i}}
\sum_s
g_id_ix_{irs}.
]

因为：

[
g_i\ge0,\qquad d_i>0,\qquad x_{irs}\ge0,
]

所以天然存在下界：

[
F_1\ge0.
]

现在已有实际求解结果表明，全本地方案可行，而且：

[
F_1=0.
]

因此：

[
0\le F_1^*\le0,
]

直接得到：

[
\boxed{F_1^*=0}.
]

这不是“求解器找到一个0”，而是：

> **下界为0 + 构造出0的可行解，因此一级目标达到严格全局最优。**

这是Q1非常有力的一条数学证书。

当前已有结果还显示所有任务级与资源级硬约束违反量均为0，因此可行性证据与最优性证据已经闭合。

---

# 3.2 不做±10%，改做“临界负载倍数”

当前全本地可行还不够——如果只增加1%的需求就必须迁移，那么这个结论其实很脆弱。

所以不人为设置：

> +5%、+10%、+20%

而是直接求**模型发生结构改变的临界点**。

定义任务负载压力系数：

[
\alpha\ge1.
]

将每个任务的GPU占用和对应AI IT功率同步放大：

[
g_i(\alpha)=\alpha g_i,
\qquad
p_i(\alpha)=\alpha p_i.
]

这样不会破坏功率映射的一致性。

定义两个临界值。

### 全本地临界倍数

[
\alpha_{\mathrm{local}}
=======================

\sup
\left{
\alpha:
F_1^*(\alpha)=0
\right}.
]

它回答：

> 当前工作负载还能整体增加多少，模型才第一次被迫跨区域迁移？

### 系统可行临界倍数

[
\alpha_{\mathrm{feas}}
======================

\sup
\left{
\alpha:
\text{存在满足全部约束的调度}
\right}.
]

它回答：

> 六区域联合调度最多能够承受多大的整体任务压力？

显然：

[
1
\le
\alpha_{\mathrm{local}}
\le
\alpha_{\mathrm{feas}}.
]

这两个数比“+10%还可行”强得多，因为它们直接给出了**模型稳定性的边界**。

---

## 3.3 如何计算临界点

不需要预先指定摄动上限。

先不断增加 (\alpha)，直到：

* 第一次出现 (F_1^*>0)，得到本地失效区间；
* 第一次出现整体不可行，得到系统失效区间。

随后在两个相邻值之间进行二分搜索，直到：

[
|\alpha_U-\alpha_L|
]

达到既定数值求解精度。

因此最终得到的是**数据和模型共同决定的临界点**，不是人为挑选几个漂亮百分比。

---

# 3.4 必须观察“非线性相变”

这个检验最有价值的地方在这里。

记录：

[
F_1^*(\alpha),\qquad
F_2^*(\alpha),
]

以及六区域峰值GPU、IT功率和设施功率利用率。

预期会出现三个阶段：

[
\alpha
<
\alpha_{\mathrm{local}}
]

时：

[
F_1^*=0,
]

全部任务继续本地完成；

当：

[
\alpha

>

\alpha_{\mathrm{local}}
]

后：

[
F_1^*>0,
]

模型开始通过跨区域迁移释放局部瓶颈；

进一步达到：

[
\alpha_{\mathrm{feas}}
]

后，即使允许迁移也无法满足全部任务约束。

因此响应不是简单线性的：

[
\boxed{
\text{全本地}
\rightarrow
\text{跨区调节}
\rightarrow
\text{系统不可行}
}
]

这正是非常有力的**结构稳健性检验**。

---

# 3.5 再把时间粒度放进同一检验，而不是单列弱检验

原来已经做过：

[
\Delta t=1h
]

与：

[
\Delta t=0.5h.
]

当前真实任务条件 (\alpha=1) 下已有：

[
F_1^{1h}=F_1^{0.5h}=0,
]

同时：

[
F_2^{1h}=3h,\qquad
F_2^{0.5h}=2h.
]

这已经说明核心区域分配不受时间粒度影响。

现在进一步分别求：

[
\alpha_{\mathrm{local}}^{1h},
\qquad
\alpha_{\mathrm{local}}^{0.5h}.
]

这样检验的不再只是：

> “当前点1h和0.5h都没迁移。”

而是：

> **两种时间粒度下，模型从“无需迁移”转变到“必须迁移”的临界压力是否接近。**

这就是参数交互：

[
\alpha\times\Delta t.
]

### 判定规则

因为没有外部统一允许差值，所以不人为设置“相差5%算稳定”。

应报告：

[
\Delta\alpha_{\mathrm{local}}
=============================

\left|
\alpha_{\mathrm{local}}^{1h}
----------------------------

\alpha_{\mathrm{local}}^{0.5h}
\right|.
]

并与：

[
\alpha_{\mathrm{local}}-1
]

这一真实鲁棒余量比较。

若粒度变化造成的临界点移动远小于模型从当前状态到失效边界的余量，则可认为时间离散误差不足以改变当前核心判断；若两者同量级，则必须承认临界容量结论对时间粒度敏感。

这里使用的是**相对判定规则**，不虚构统一阈值，符合提示词要求。

---

# 最终只保留这3项检验

我建议直接砍掉上一版那些强度不够的普通检查，第一问正式检验就是：

### **检验一：滚动时间外预测与聚合尺度泛化检验**

防守：

> 聚合提高预测稳定性不是单个24h窗口的偶然结果。

核心证据：

[
\text{rolling-origin}
+
\text{paired WAPE}
+
\text{Wilcoxon }p<0.05.
]

---

### **检验二：分层结构恢复有效性检验**

防守：

> 聚合预测再恢复18类没有牺牲题目要求的区域×类型结构。

核心证据：

[
\text{边际闭合}
+
\text{JS结构稳定性}
+
\text{Hierarchical vs Direct成对预测误差}.
]

---

### **检验三：一级最优性证书与临界负载压力检验**

防守：

> (F_1=0) 不只是一个偶然可行结果，而且在一定负载余量内稳定成立。

核心证据：

[
F_1\ge0
+
F_1=0\text{可行构造}
\Rightarrow
F_1^*=0,
]

再求：

[
\alpha_{\mathrm{local}},
\qquad
\alpha_{\mathrm{feas}},
]

并检查：

[
\alpha\times\Delta t
]

交互下的临界边界。

## 为什么这套检验比“普通灵敏度分析”强

因为最终你可以回答三个很硬的问题：

> **预测真的能泛化吗？**

不是“验证日误差还行”，而是多个严格时间外窗口 + 显著性检验。

> **为了降低误差做聚合，有没有把不同区域和任务类型搞丢？**

不是“行列和对得上”，而是结构先验稳定性 + 历史真实交叉单元的样本外恢复误差。

> **100%本地执行到底有多可信？**

不是“求解器这次得到0”，而是：

[
\underbrace{F_1\ge0}*{理论下界}
+
\underbrace{F_1=0\text{可行解}}*{构造上界}
\Rightarrow
\boxed{F_1^*=0}
]

再给出任务负载增加到什么程度才会第一次出现迁移、什么时候整个系统失去可行性的**临界边界**。

这才符合你提示词里说的：检验必须能够改变或保卫**模型采用、参数选择、结果解释和论文结论**，而不是做一套形式化检查表。

目前真正已经有实际结果的是调度部分的 (F_1=0)、100%本地执行、硬约束零违反以及1h/0.5h下 (F_2=3/2h)；**滚动预测、JS结构稳定性和临界负载 (\alpha) 还没有实际运行，所以现在只能按提示词给出上述检验设计，不能提前写“通过”。**
