## 1. 总体理解

### 1.1 研究对象

题目研究的是由六个区域组成的跨区域人工智能算力系统。系统中的任务从不同区域到达，在满足任务时延、完成期限、GPU容量、IT功率、设施功率等约束的前提下，决定任务在哪个区域执行、何时开始执行，以及各区域的电力和储能如何协同。

六个区域的题面角色如下：

| 区域 | 题面定位 | 审题含义 |
|---|---|---|
| RegionA、RegionB、RegionC | 东部高负载区域 | 有实时任务需求和算力压力，区域间承担用户侧任务与迁移比较 |
| RegionD | 西部算力中心 | 计算容量较大，适合承接可延迟的批处理或训练任务 |
| RegionE | 光伏资源较丰富区域 | 具有较明显的日内新能源变化，涉及低碳消纳和选址比较 |
| RegionF | 风电资源较丰富区域 | 新能源波动和储能协同是重要关注点 |

上述“适合”只表示题面给出的区域角色，不等于已经得到调度结论。具体任务是否能迁移、迁移到哪里、何时执行，仍须由任务类型、时延、资源和电力约束共同决定。

### 1.2 核心矛盾

题面要求同时处理以下几类关系：

- 算力任务的到达、延迟执行和完成期限之间的关系；
- 实时服务质量与跨区域网络时延之间的关系；
- GPU占用、人工智能IT功率和设施总负荷之间的关系；
- 区域电价、购售电、碳排放和新能源可用量之间的关系；
- 新能源波动、储能充放电和区域净购电峰值之间的关系；
- 成本、碳排放、网络时延、服务质量、新能源利用和峰值购电之间的取舍关系。

因此，最终答案不能只给“任务放在哪里”，也不能只给“储能怎么充放电”。需要把任务级安排、逐时负荷、能源分配、储能状态和评价指标连成可复核的证据链。

### 1.3 全题需要形成的结果类型

题面实际要求的结果可分为四层：

1. **任务与算力层**：按区域、任务类型分析GPU需求，给出任务的执行区域、开始时间、结束时间及尾部任务处理安排。
2. **电力与碳排层**：在统一功率口径下，计算购电、售电、碳排放、新能源使用和新能源利用率等逐时及汇总指标。
3. **储能层**：给出各区域储能的充电、放电、荷电状态及其对成本、碳排放、峰值净购电和负荷波动的影响。
4. **综合比较层**：在不同碳约束、电价机制和新能源波动情景下，形成策略对照，并说明各指标之间的变化关系。

## 2. 题面深挖

### 2.1 时间边界和执行语义

| 时间段 | 题面含义 | 审题结论 |
|---|---|---|
| 第0—2399小时 | 主要运行期；任务到达数据覆盖此区间 | Q1的预测评估窗口和Q1末段调度要重点区分；Q2—Q4的主要运行时段也是此区间 |
| 第2400—2405小时 | 不再产生新任务，只允许处理已经到达但尚未完成的尾部任务 | 尾部任务可以延续执行，但不能把这段时间当作新的任务到达期 |
| 第2406小时 | 不安排新任务，也不能有未完成任务，只进行终端功率或储能状态结算 | 所有任务须在2406小时前完成；2406不是可继续执行任务的普通运行小时 |

题面同时规定：任务不能被抢占、拆分或在执行中途迁移；实时推理任务到达后开始执行，批处理推理和训练任务允许延迟，但必须在规定期限前完成。`EstimatedDuration_min`以分钟记录，逐时资源占用需要按任务在小时内的实际重叠时长核算。

### 2.2 任务类型和时延语义

| 任务类型 | 题面特征 | 调度时必须保留的要求 |
|---|---|---|
| RealTimeInference | 时延敏感度高 | 到达后启动，并满足`MaxLatency_ms`对应的服务要求；长距离迁移通常会受到限制 |
| BatchInference | 时延敏感度中等 | 可以在一定范围内延迟，在成本、时延和容量之间权衡 |
| AITraining | 时延敏感度低 | 具有较强的时间和区域灵活性，是低成本、低碳或新能源消纳安排的主要候选任务 |

“通常不长距离迁移”是附件中的场景说明，不应直接当成一条未经核验的硬约束。真正的可行性仍需由任务的时延字段、区域间时延表和题面任务规则共同判定。

### 2.3 统一功率和能源口径

附件1给出了全题统一口径。审题阶段必须先锁定以下关系：

- 人工智能IT负荷由任务的等效GPU需求、任务在区域和小时内的实际重叠时长，以及任务类型对应的单位等效GPU功率共同决定；
- 区域总IT负荷等于固定的非人工智能IT负荷与人工智能IT负荷之和；
- 设施总负荷等于总IT负荷乘以该区域PUE；
- 功率平衡需要同时考虑购电、可用新能源、放电、充电、售电和弃电；
- 碳排放按电网购电量乘以碳强度计算；
- 新能源利用率的分子包括直接消纳、用于储能充电和对外出售的新能源，分母为累计可用新能源。

这意味着不能把附件中的`IT_Load_MW`或`Total_Load_MW`直接当作所有问题都固定不变的总负荷。Q2和Q4需要根据任务安排重新计算人工智能IT负荷；Q3则有题面特别指定的固定负荷口径，见第4.3节。

## 3. 四个问题逐问拆解

### 3.1 Q1：工作负载分析、短期预测与末段基础调度

| 项目 | 审题结论 |
|---|---|
| 核心问题 | 按区域和任务类型分析GPU需求，完成短期预测，并对第2376—2399小时实际到达的任务安排执行时间和执行区域；对跨越主要运行期的任务处理尾部执行，给出末段任务甘特图和区域GPU利用率 |
| 任务类型 | 预测 + 评价 + 调度 |
| 直接输入 | `workload_trace.xlsx`中的任务到达、任务类型、GPU需求、持续时间、时延和最晚完成时间；`GPU_information.xlsx`中的区域算力和功率边界 |
| 主要输出 | 区域/任务类型GPU需求分析；短期预测结果及预测评价；第2376—2399小时任务级执行安排；尾部任务完成安排；末段甘特图；区域GPU利用率 |
| 评价对象 | 预测评价只针对题面指定的末段24小时窗口；末段调度使用实际到达任务，不得用预测值替代实际任务 |
| 依赖关系 | 可以独立完成，不应把Q1预测结果误认为Q2—Q4必须使用的任务输入；Q4是否引用Q1调度结果需在后续统一口径 |
| 主要误读点 | “预测窗口”和“实际调度窗口”不是同一件事；尾部任务可以在2400—2405小时继续处理，但不能有新任务；任务不可抢占、拆分或中途迁移 |

Q1的“短期预测”没有在题面中完整规定预测对象的唯一表达方式、预测评价指标和合格阈值。末段24小时是明确的评价窗口，但“用什么指标评价”和“是否需要设定通过标准”属于`【需核验】`事项，不能在审题阶段自行写成题面结论。

Q1的“基础算力调度”也没有明确成本、时延、均衡或其他目标的优先级。后续若要给出调度结果，必须把采用的优先级或评价口径单独记录，不能把团队约定伪装成题面要求。

### 3.2 Q2：考虑电价、碳和新能源的任务调度

| 项目 | 审题结论 |
|---|---|
| 核心问题 | 在第0—2399小时实际任务和对应逐时功率参数基础上，同时决定任务迁移区域和开始时间，形成兼顾电价、碳排放、网络时延和新能源利用的调度策略 |
| 任务类型 | 优化决策 + 多指标评价 |
| 直接输入 | `workload_trace.xlsx`、`GPU_information.xlsx`、`network_latency.xlsx`、`region_time_data.xlsx`、`power_mapping.xlsx` |
| 主要输出 | 任务级执行区域、开始时间、结束时间；逐时GPU和人工智能IT负荷；成本、碳排放、网络时延、新能源利用率；任务和区域约束核验；策略解释 |
| 关键口径 | Q2使用实际任务和实际逐时功率参数；人工智能IT负荷按统一功率映射重新计算；固定非人工智能IT负荷不能被任务调度改变 |
| 依赖关系 | 直接依赖附件数据，不等同于把Q1的预测负荷作为输入；其任务调度和评价结果可能成为Q4综合安排的基础 |
| 主要误读点 | 不能只按电价迁移任务；实时任务必须满足到达启动和网络时延要求；不能用总IT负荷固定不变的方式掩盖任务迁移造成的人工智能IT负荷变化 |

Q2明确列出多个目标，但没有规定它们之间是加权、分层、约束式还是其他关系，也没有规定唯一的策略选取标准。该部分属于`【信息缺口】`，后续必须以可解释、可复核的团队口径补齐，并在论文中与题面原要求区分。

是否必须与附件基准状态做统一对比，题面未对Q2单独作出完整的展示要求；但附件说明要求优化结果与基准状态具有可比较性，因此“是否展示基准、展示哪些指标”应列为`【待确认】`的交付事项。

### 3.3 Q3：储能协同与影响分析

| 项目 | 审题结论 |
|---|---|
| 核心问题 | 在给定任务安排和逐时负荷基础上，只决定储能充放电、购售电和新能源分配，分析储能对运行成本、碳排放、区域峰值净购电功率和负荷波动程度的影响 |
| 任务类型 | 储能决策 + 影响评价 |
| 直接输入 | `region_time_data.xlsx`中的`Baseline_AI_IT_Load_MW`、`NonAI_IT_Load_MW`及电力数据；`storage_information.xlsx`中的储能边界；区域PUE和统一能源口径 |
| 主要输出 | 各区域逐时充电功率、放电功率、SOC、购电、售电、新能源分配和弃电；成本、碳排放、峰值净购电功率、负荷波动程度的对比与解释 |
| 关键口径 | Q3不重新决定任务迁移和开始时间；只优化储能与电力侧变量；初始SOC取`InitialSOC_MWh`，而`region_time_data.xlsx`中的`SOC_MWh`是基准状态的小时末状态 |
| 依赖关系 | 依赖固定的任务负荷口径和区域逐时数据；在全题逻辑上承接Q2/Q1的任务安排，但附件说明对Q3的固定负荷口径有特别规定，必须优先执行并在论文中说明 |
| 主要误读点 | 不能把Q3改写成重新调度任务；不能把基准SOC当作优化初始SOC；不能忽略充放电效率、SOC边界、充放电功率边界、购售电边界和终端SOC要求 |

“在给定任务调度和逐时负荷基础上”容易造成歧义。附件1已经进一步规定：Q3使用`Baseline_AI_IT_Load_MW`和`NonAI_IT_Load_MW`作为给定IT负荷，只优化储能充放电、购售电和新能源分配，不重新优化迁移和开始时间。此条应作为Q3的优先解释。

“负荷波动程度”没有给出唯一计算式。至少需要在后续明确统计对象是总负荷、净购电还是其他负荷序列，以及采用逐时变化、峰谷差、波动幅度或其他可复核口径；当前标记为`【需核验】`，不能直接写成题面定义。

### 3.4 Q4：算力—储能—电力多区域协同

| 项目 | 审题结论 |
|---|---|
| 核心问题 | 综合考虑任务迁移、开始时间、电价、碳排放、新能源、储能、区域购售电边界、时延和任务异质性，形成跨区域算力—储能—电力协同安排，并比较不同外部情景下的策略变化 |
| 任务类型 | 综合决策 + 多目标评价 + 情景比较 |
| 直接输入 | Q1—Q3形成的可复核口径和相关数据，以及六个附件数据工作簿；具体固定输入需进一步锁定 |
| 主要输出 | 任务级综合执行安排；区域逐时GPU、IT负荷、设施负荷、购售电、新能源和储能状态；成本、碳排放、网络时延、服务质量、新能源利用、区域峰值净购电等指标；不同碳约束、电价机制和新能源波动情景的对照 |
| 关键口径 | 必须沿用统一功率映射、任务不可抢占/拆分/中途迁移、时延边界、储能边界和终端状态要求 |
| 依赖关系 | 题面表述为“基于Q1—Q3”，但没有逐项规定Q1预测、Q1调度、Q2调度和Q3固定负荷之间哪些必须作为固定输入；该输入继承关系为`【待确认】` |
| 主要误读点 | 不能把综合题扩展为电网潮流、带宽、迁移数据量、传输能耗或传输费用问题；附件明确将这些内容排除在建模边界之外 |

Q4中的“服务质量”需要由任务类型、到达启动、最大网络时延、完成期限等可核验要求来表达；若团队另行引入新的服务质量指标，必须说明来源和必要性，不能声称该指标是题面原始定义。

“不同碳约束、电价机制和新能源波动场景”没有直接给出参数取值、区间、场景数量或变化方式，属于`【信息缺口】`。后续情景设计必须记录基准、变化因素、保持不变的输入和比较指标，保证不同场景之间可比。

## 4. 小问依赖关系

```text
题面与附件统一口径
        |
        +--> Q1：工作负载分析、短期预测、末段基础调度
        |
        +--> Q2：实际任务下的碳/电价/新能源感知调度
        |          |
        |          +--> 可为Q4提供任务调度和逐时负荷的候选结果
        |
        +--> Q3：固定任务负荷口径下的储能与电力侧协同
        |          |
        |          +--> 可为Q4提供储能和能源侧边界、比较口径
        |
        +--> Q4：综合协同与情景比较
                   |
                   +--> 需要在赛中锁定“承接哪些前三问结果”
```

依赖关系的审题结论：

1. Q1的末段预测评价与末段实际任务调度必须分开保存；预测结果不能替代实际到达任务。
2. Q2的题面输入是第0—2399小时实际任务和实际功率参数，不应默认引用Q1预测值。
3. Q3不能把任务迁移和开始时间重新作为决策；它有独立的固定负荷口径。
4. Q4在逻辑上承接前三问，但具体承接哪些结果、哪些变量重新决定，必须在赛中形成一页“输入冻结表”，否则容易重复计算或混用基准数据。

## 6. 约束与风险清单

### 6.1 硬约束清单

| 类别 | 必须满足的约束 |
|---|---|
| 任务执行 | 任务不可抢占、不可拆分、不可执行中途迁移；任务占用GPU应覆盖完整执行区间 |
| 实时任务 | 到达后启动，并满足相应最大时延要求 |
| 批处理/训练 | 可以延迟，但必须在规定期限前完成，且所有任务在2406小时前完成 |
| 算力 | 每个区域每小时任务GPU占用不得超过该区域可用GPU能力 |
| 功率 | IT功率和设施功率不得超过区域对应上限；人工智能IT功率按统一映射计算 |
| 网络 | 迁移后的任务必须满足题面时延要求；仅使用单向区域间网络时延 |
| 电力 | 按统一功率平衡计算购电、可用新能源、充放电、售电和弃电；满足区域最大购电/售电边界 |
| 储能 | 满足容量、最小/最大SOC、最大充放电功率、充放电效率和初始状态要求；终端SOC不低于初始SOC |
| 时间 | 第2400—2405小时只处理尾部任务；第2406小时不再安排任务，只结算终端功率或储能状态 |
| Q3边界 | 不重新优化任务迁移和开始时间，仅处理给定负荷下的储能和电力侧变量 |
| Q4边界 | 不增加潮流、带宽、迁移数据量、传输能耗或传输费用等题面未要求的变量 |

### 6.2 单位和边界风险

- `GPU_Demand`是等效GPU需求，不应与实体GPU数量混用。
- `EstimatedDuration_min`是分钟；逐时GPU小时需要按实际重叠时长折算，不能把每个跨小时任务完整时长重复计入每个小时。
- 功率字段多以MW表示，储能状态以MWh表示；充放电功率与小时长度之间必须保持单位一致。
- 电价和售电价以元/MWh表示，碳强度以tCO2/MWh表示，网络时延以ms表示。
- `InitialSOC_MWh`是小时0之前的初始状态；`SOC_MWh`是基准数据的小时末状态，二者不能直接互换。
- `MaxGridImport_MW`和`MaxGridExport_MW`是区域边界，不能解释为区域之间可以相互传输电力。

## 7. 重点误读风险

按“现象—正确口径—检查方法”记录，赛中每次改动后都应复核。

### 风险1：把预测值用于Q1末段实际调度

- 现象：用预测的任务量替代第2376—2399小时已经给出的实际到达任务。
- 正确口径：末段24小时的预测只用于预测评价；末段基础调度使用实际到达任务。
- 检查方法：任务调度表中的任务编号必须能回溯到`workload_trace.xlsx`，并核对到达小时。

### 风险2：把Q2和Q4的总IT负荷固定不变

- 现象：任务迁移后仍直接沿用附件中的总IT负荷。
- 正确口径：固定的是非人工智能IT负荷；人工智能IT负荷要根据新的任务执行区域、执行区间和统一功率映射重新计算。
- 检查方法：抽查迁移前后任务占用和区域人工智能IT负荷，确认两者可逐时对应。

### 风险3：Q3重新安排任务

- 现象：在储能问题中再次改变任务迁移区域或开始时间。
- 正确口径：Q3只优化储能充放电、购售电和新能源分配，任务负荷按附件规定的给定口径处理。
- 检查方法：Q3输出中不应出现新的任务开始时间、结束时间或执行区域决策列。

### 风险4：混淆2400—2405小时和2406小时

- 现象：把2406小时当作任务继续执行的普通小时，或者在2400—2405小时安排新到达任务。
- 正确口径：2400—2405小时只收尾；2406小时不安排新任务、不允许未完成任务，只做终端状态结算。
- 检查方法：检查任务到达、任务结束、SOC结算和最终未完成任务清单。

### 风险5：错误处理分钟时长和小时重叠

- 现象：一个跨小时任务在每个覆盖小时重复计入完整`EstimatedDuration_min`。
- 正确口径：按任务在具体小时内的实际重叠时长计算GPU小时和功率贡献。
- 检查方法：单任务抽查执行起止边界，确认各小时重叠时长之和等于任务总执行时长。

### 风险6：把网络时延表扩展成带宽或传输成本约束

- 现象：根据区域距离或时延自行增加迁移数据量、带宽、传输能耗或传输费。
- 正确口径：本题网络侧只使用题面给出的单向时延；附件明确不要求上述扩展。
- 检查方法：检查约束和指标字段，排除未经授权的网络能耗、线路容量和传输费。

### 风险7：自行编造多目标权重并当作题面要求

- 现象：论文中直接写出某个成本、碳排放或时延的权重，却不说明来源。
- 正确口径：题面只明确需要同时考虑多个目标，没有给出唯一权衡方式。团队口径必须单独标注并提供比较依据。
- 检查方法：所有权重、优先级、阈值和情景参数均应有“题面给定”或“团队设定”的来源标签。

### 风险8：错误计算新能源利用率

- 现象：只用直接供给任务的新能源作为分子，忽略储能充电或对外出售。
- 正确口径：按附件统一定义，分子包括直接消纳、储能充电和新能源对外出售，分母为累计可用新能源。
- 检查方法：逐时核对可用新能源的去向，确认分子各项不重复、不漏计。

### 风险9：错误计算碳排放

- 现象：用设施总负荷、总用电量或净购电量直接替代电网购电量。
- 正确口径：碳排放按电网购电量乘以对应小时碳强度计算。
- 检查方法：逐时检查碳排放字段是否与购电量和碳强度相乘一致。

## 8. 建模前必须锁定的事项

以下事项未锁定前，不应把结果写成最终结论：

1. **Q1预测评价**：明确预测对象、评价窗口、评价指标、是否需要阈值，以及预测评价和实际调度的分离方式。
2. **任务时间边界**：明确小时边界采用的区间约定，统一`EstimatedDuration_min`、`LatestFinishHour`和2406终止边界。
3. **任务输出表**：至少固定任务编号、原始来源区域、执行区域、到达时间、开始时间、结束时间、任务类型、GPU需求和可行性核验字段。
4. **逐时输出表**：至少固定区域、小时、任务GPU占用、人工智能IT负荷、非人工智能IT负荷、总IT负荷、设施负荷、购电、售电、新能源去向和储能状态字段。
5. **Q2目标表达**：明确成本、碳排放、时延、新能源利用之间的报告顺序、比较方式和选择标准；所有新增权重或阈值标注为团队口径。
6. **Q3波动指标**：明确“负荷波动程度”的序列对象、统计窗口、计算公式和基准状态。
7. **Q3基准对比**：明确储能影响是与无储能状态、附件基准状态，还是其他统一状态比较，并保持输入一致。

10. **数据质量检查**：进入求解前检查任务编号重复、字段缺失、类型取值、时间范围、负数或超边界值、区域名称一致性和时延矩阵完整性，并保存审计结果。
